# Writing Style Rule

문서·보고서·티켓 본문을 작성할 때 적용되는 규칙.

## 전체 규칙은 별도 파일에 있다

**`.claude/docs/writing-style.md` 를 읽고 나서 쓴다.** 장별 골격, Confluence
매크로, 발행 정책, 체크리스트, 기준 문서의 암묵적 패턴이 모두 거기 있다.
이 파일은 포인터이고, 내용을 여기에 복사하지 않는다 — 두 곳에 같은 규칙이
있으면 반드시 어긋난다.

이 규칙 파일은 매 세션 로드되고 전체 스타일 문서는 400줄이 넘으므로,
문서를 쓰지 않는 세션의 컨텍스트를 아끼기 위해 분리했다.

## 언제 읽는가

- Confluence 페이지를 쓰거나 고칠 때
- Jira 티켓 본문을 채울 때
- 저장소 안의 준거·감사 문서, 구현 계획서를 쓸 때
- 사용자가 "문서로 정리해줘", "보고서 써줘" 류를 요청할 때

코드 주석·docstring·커밋 메시지에는 적용하지 않는다. 그것은
`.claude/rules/language.md` 와 `coding-principles.md` 를 따른다.

## 전체 문서를 읽지 않고도 절대 위반하면 안 되는 것

정직성 관련 항목은 예외 없이 적용된다.

- **확인하지 않은 것을 단정하지 않는다.** 조항 번호·CVE·해시·버전을 기억으로
  쓰지 않는다. 원문 대조가 없으면 쓰지 않는다.
- **측정하지 않은 것을 측정한 것처럼 쓰지 않는다.** 성공 로그만 보고 "통과"라고
  쓰지 않는다 — 출력은 검증이 아니다.
- **[확인함] / [추론] / [미확인] 을 구분해 표기한다.** 확인 수단이 막혔으면 그
  사실 자체를 적고 사람이 할 일을 남긴다.
- **이전에 쓴 것이 틀렸으면 조용히 고치지 않는다.** 무엇이 왜 틀렸는지 남긴다.
- **좋게 들리는 요약으로 나쁜 사실을 덮지 않는다.** 한계를 먼저 쓴다.

사실이 불확실할 때는 이 원칙이 문서 구조·서식 규칙 전부를 앞선다.
