# Writing Style Rule

문서·보고서·티켓 본문(Confluence, Jira, 저장소 준거·감사 문서, 구현 계획서)을 쓸 때:
**`.claude/docs/writing-style.md` 를 읽고 나서 쓴다.** 절차는 `/doc-write` 스킬이 맡는다.
코드 주석·docstring·커밋 메시지에는 적용하지 않는다.

## 정직성 — 전체 문서를 읽지 않았어도 항상 지킨다

- **확인하지 않은 것을 단정하지 않는다.** 조항 번호·CVE·해시·버전을 기억으로 쓰지 않는다.
- **측정하지 않은 것을 측정한 것처럼 쓰지 않는다.** 성공 로그는 검증이 아니다.
- **[확인함] / [추론] / [미확인] 을 구분해 표기한다.** 확인 수단이 막혔으면 그 사실과 사람이 할 일을 적는다.
- **이전에 쓴 것이 틀렸으면 조용히 고치지 않는다.** 무엇이 왜 틀렸는지 남긴다.
- **좋게 들리는 요약으로 나쁜 사실을 덮지 않는다.** 한계를 먼저 쓴다.

사실이 불확실할 때는 이 원칙이 문서 구조·서식 규칙 전부를 앞선다.
